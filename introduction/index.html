The glue:

A2A Protocol

Agent-to-Agent — open standard

🏛️ Now part of the Agentic AI Foundation

📋 AgentCard

Self-describing capability manifest at /.well-known/agent.json

📨 SendMessage

Structured tasks with streaming & async support

📡 Multiple transports

JSON-RPC REST gRPC

"Any runtime, any language — if it speaks A2A, it joins the mesh"

A2A started as a Google-led open protocol. It's now under the Agentic AI Foundation, which gives it proper open governance. It defines how agents advertise capabilities via an AgentCard and exchange tasks. It supports three transports: JSON-RPC, REST, and gRPC — so whatever your stack, there's a transport that fits.

Workshop agenda

💬 Exercise 1 — Your First A2A Agent — Quarkus + A2A Java SDK, AgentCard, AgentExecutor, @RegisterAiService tool calling (30 min)
🏢 Exercise 2 — Cross-Runtime Agents — Spring Boot + spring-a2a, IoT room capacity, indoor navigation (20 min)
🐍 Exercise 3 — Cross-Language Interop — Python A2A SDK, transit comparison, Java ↔ Python over A2A (15 min)
💳 Exercise 4 — Expense & Compliance Agent — WildFly 41 + Jakarta EE, compliance rules, JAX-RS A2A client (20 min)
🧠 Exercise 5 — The Orchestrator — @SupervisorAgent, @A2AClientAgent, multi-tenant Concierge, web UI (25 min)
🚀 Exercise 6 — Load-Balanced A2A (Bonus) — WildFly × 2, shared PostgreSQL task store, Kafka cross-node event replication

Each exercise has a exercises/ skeleton and a solutions/ reference — work at your own pace.

Five main exercises, one bonus. Each one is self-contained — if you fall behind on one, grab the solution and move on. The exercises are designed to be done in order: each one's output is the next one's input. By Exercise 5, all four agents are wired together.
