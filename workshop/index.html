Architecture

A2A Protocol in 60 seconds

The Agent-to-Agent (A2A) protocol is an open standard for agent interoperability. Every A2A agent exposes:

  • AgentCard at /.well-known/agent-card.json — machine-readable identity: name, skills, capabilities, endpoint
  • JSON-RPC endpoint for SendMessage — send messages and receive Task responses
  • Task lifecycle — SUBMITTED → WORKING → COMPLETED (or FAILED)

        ObjectMapper mapper = new ObjectMapper();
        Path path = Path.of(sessionDataPath);
        sessions = mapper.readValue(path.toFile(), new TypeReference<>() {});

                        || s.track().toLowerCase().contains(q)
                        || s.speaker().toLowerCase().contains(q)
                        || s.description().toLowerCase().contains(q)
                        || s.tags().stream().anyMatch(t -> t.contains(q)))
                .toList();
        // format and return results...
    }

    @Tool("List all available conference tracks.")
    public String listTracks() { ... }

    @Tool("Get the schedule for a specific date (YYYY-MM-DD).")
    public String getScheduleByDate(String date) { ... }

    @Tool("Filter sessions starting at or after a given time on a date.")
    public String filterSessionsAfterTime(String date, String time) { ... }

    @Tool("Get speaker information by name.")
    public String getSpeakerInfo(String speakerName) { ... }

4 Implement the AgentExecutor

The AgentExecutor receives incoming A2A messages and produces responses through the emitter pattern.

Open ScheduleAgentExecutorProducer.java and implement the agentExecutor() method. Return an anonymous class that implements AgentExecutor with two methods:

  1. execute(RequestContext context, AgentEmitter emitter)
    1. Extract the plain text from the incoming message: iterate context.getMessage().parts(), collect the text from each TextPart into a single string
    2. Call emitter.startWork() to signal the task has started
    3. Call scheduleService.chat(userText) to get the LLM response
    4. On success: call emitter.addArtifact(Collections.singletonList(new TextPart(response)), null, "response", null), then emitter.complete()
    5. On exception: call emitter.addArtifact(...) with the error message, then emitter.fail()
  2. cancel(RequestContext context, AgentEmitter emitter) — throw new TaskNotCancelableError()

The flow maps directly to the Task lifecycle:

Client sends SendMessage
  → execute() called
  → emitter.startWork()          → Task state: WORKING
  → scheduleService.chat()       → LLM + tool calls happen
  → emitter.addArtifact()        → Attach response content
  → emitter.complete()           → Task state: COMPLETED
  → Response returned to client

The AgentExecutor producer method is annotated with @Produces and @ApplicationScoped so each node shares one executor instance. The AgentExecutor uses an init handshake pattern to split task creation from task execution, allowing the client to subscribe on a different node before the work begins:

Show EnterpriseAgentExecutorProducer.java 
@Override
public void execute(RequestContext context, AgentEmitter emitter) throws A2AError {
    boolean isNewTask = context.getTask() == null;
    if (isNewTask) {
        emitter.submit();  // persist task in JPA store, publish SUBMITTED event to Kafka
    }

    // Special convention: messageId "init" creates the task and returns immediately.
    // The client can then resubscribe via a *different node* before sending the real work.
    boolean isInitHandshake = isNewTask && "init".equals(context.getMessage().messageId());
    if (isInitHandshake) {
        return;  // task is SUBMITTED, open for continuation
    }

    emitter.startWork();         // publish WORKING event → broadcast to all nodes

    String text   = extractText(context.getMessage().parts());
    String result = isSummaryRequest(text)
            ? feedbackStore.buildSummary(extractSpeaker(text), extractSession(text))
            : handleFeedbackSubmission(text);  // parses speaker, session, rating, comment → persists to PostgreSQL

    emitter.addArtifact(Collections.singletonList(new TextPart(result)), null, "response", null);
    emitter.complete();          // publish COMPLETED + artifact → Node B receives it via Kafka
}
💡 Why the init handshake?

The demo needs to prove that Node B receives events it never produced locally. The init message creates the task on Node A, then the client resubscribes via Node B. When Node A later sends the WORKING → COMPLETED transition, those events travel through Kafka and arrive at Node B’s SSE stream — which Node B then relays to the waiting client.

💡 What this proves

Node B had no local record of the task. It found it in the shared JPA TaskStore (PostgreSQL) and subscribed to its event stream. The WORKING and COMPLETED state changes arrived via Kafka replication. The feedback itself is stored in PostgreSQL, so a summary requested on Node B returns all submissions made via Node A. This is what makes the system horizontally scalable: any node behind a load balancer can answer GetTask, serve a subscription stream, or query business data for any task.

Troubleshooting

⚠ OpenAI API authentication or quota errors

Check that OPENAI_API_KEY is set to a valid key and that API billing is enabled. ChatGPT subscriptions do not cover API usage, and the GPT-6 Luna API Free tier is unsupported.

⚠ Empty or slow responses

LLM response times depend on the API request. If a request times out, check the agent logs and increase the configured timeout if needed.

⚠ "No sessions found"

Verify that session.data.path in application.properties points correctly to conference-data/sessions.json relative to the project directory.

⚠ A2A SDK not found

The A2A Java SDK is not on Maven Central. Build it from source: git clone https://github.com/a2aproject/a2a-java.git && cd a2a-java && mvn install -DskipTests

⚠ Python agent won't start

Make sure you activated the virtual environment (source .venv/bin/activate) and installed dependencies (pip install -e .). Python 3.11+ is required.

⚠ Port conflict

If port 8080 is already in use, check that no other agent or service is running on that port. The Schedule Advisor (Quarkus) runs on 8080 and the Expense Agent (WildFly) uses -Djboss.socket.binding.port-offset=2 to run on 8082.
