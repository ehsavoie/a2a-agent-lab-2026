In this hands-on lab you will progressively build DevSphere — a multi-agent system that helps conference attendees with sessions, venue logistics, travel, and expense reporting. Each exercise adds a new agent to the ecosystem.

Architecture

A2A Protocol in 60 seconds

The Agent-to-Agent (A2A) protocol is an open standard for agent interoperability. Every A2A agent exposes:

  • AgentCard at /.well-known/agent-card.json — machine-readable identity: name, skills, capabilities, endpoint
  • JSON-RPC endpoint for SendMessage — send messages and receive Task responses
  • Task lifecycle — SUBMITTED → WORKING → COMPLETED (or FAILED)

1 Build the ScheduleTool

The ScheduleTool is an @ApplicationScoped CDI bean that gives the LLM access to the real conference data. LangChain4j’s @Tool annotation exposes methods as callable tools that the model can invoke.

Open src/main/java/dev/devconf/schedule/ScheduleTool.java:

Show ScheduleTool.java 
@ApplicationScoped
public class ScheduleTool {

    @ConfigProperty(name = "session.data.path")
    String sessionDataPath;

    private List<Session> sessions;

    @PostConstruct
    void init() {
        ObjectMapper mapper = new ObjectMapper();
        Path path = Path.of(sessionDataPath);
        sessions = mapper.readValue(path.toFile(), new TypeReference<>() {});
    }

    @Tool("Search conference sessions by keyword, track, speaker name, or tag.")
    public String searchSessions(String query) {
        String q = query.toLowerCase();
        List<Session> matches = sessions.stream()
                .filter(s -> s.title().toLowerCase().contains(q)
                        || s.track().toLowerCase().contains(q)
                        || s.speaker().toLowerCase().contains(q)
                        || s.description().toLowerCase().contains(q)
                        || s.tags().stream().anyMatch(t -> t.contains(q)))
                .toList();
        // format and return results...
    }

    @Tool("List all available conference tracks.")
    public String listTracks() { ... }

    @Tool("Get the schedule for a specific date (YYYY-MM-DD).")
    public String getScheduleByDate(String date) { ... }

    @Tool("Filter sessions starting at or after a given time on a date.")
    public String filterSessionsAfterTime(String date, String time) { ... }

    @Tool("Get speaker information by name.")
    public String getSpeakerInfo(String speakerName) { ... }

    public record Session(
        String id, String title, String speaker, String track,
        String room, String date, String time, int duration,
        String description, List<String> tags
    ) {}
}
💡 Key tool: filterSessionsAfterTime

Maya arrives at 9:45 AM. This tool lets the LLM exclude sessions she already missed, finding talks starting at 10:15 or later that match her interests.

2 Build the ScheduleService

The ScheduleService is a Quarkus LangChain4j AI Service — an interface annotated with @RegisterAiService that Quarkus automatically wires to the LLM and tools.

Show ScheduleService.java 
@RegisterAiService(tools = ScheduleTool.class)
public interface ScheduleService {
    @SystemMessage("""
            You are the DevConf 2026 Schedule & Content Advisor.
            You deep-scan the session catalog, speaker bios, and tracks.
            If the attendee mentions arriving late, use filterSessionsAfterTime.
            Always use your search tools rather than making up information.
            """)
    String chat(@UserMessage String userMessage);
}
💡 Quarkus LangChain4j pattern

@RegisterAiService(tools = ScheduleTool.class) tells Quarkus to auto-wire the LLM (configured in application.properties) with the schedule tools. No manual AiServices.builder() needed — Quarkus handles the CDI plumbing.

3 Implement the AgentCard Producer

The AgentCard is how your agent introduces itself to the A2A world. It is served at /.well-known/agent-card.json and tells other agents what you can do.

Show ScheduleAgentCardProducer.java 
@ApplicationScoped
public class ScheduleAgentCardProducer {

    @Produces
    @PublicAgentCard
    public AgentCard agentCard() {
        return AgentCard.builder()
                .name("Schedule & Content Advisor")
                .description("Deep-scans the DevConf session catalog...")
                .version("1.0.0")
                .skills(List.of(
                    AgentSkill.builder()
                        .id("session-search")
                        .name("Session Search")
                        .description("Search sessions by topic, speaker, or track.")
                        .build(),
                    AgentSkill.builder()
                        .id("session-recommend")
                        .name("Session Recommendations")
                        .description("Personalized recommendations based on interests.")
                        .build(),
                    AgentSkill.builder()
                        .id("speaker-info")
                        .name("Speaker Information")
                        .description("Get speaker bios and session history.")
                        .build()
                ))
                .build();
    }
}
💡 CDI pattern

@Produces makes this a CDI producer method. @PublicAgentCard is an SDK qualifier that tells the A2A Jakarta transport to serve this card at /.well-known/agent-card.json automatically.

4 Implement the AgentExecutor

The AgentExecutor receives incoming A2A messages and produces responses through the emitter pattern.

Show ScheduleAgentExecutorProducer.java 
@ApplicationScoped
public class ScheduleAgentExecutorProducer {

    @Inject
    ScheduleService scheduleService;

    @Produces
    public AgentExecutor agentExecutor() {
        return new AgentExecutor() {
            @Override
            public void execute(RequestContext context, AgentEmitter emitter) {
                String userText = extractText(context.getMessage());

                emitter.startWork(emitter.messageBuilder()
                    .parts(List.of(new TextPart("Scanning the schedule...")))
                    .build());

                try {
                    String response = scheduleService.chat(userText);
                    emitter.addArtifact(List.of(new TextPart(response)));
                    emitter.complete();
                } catch (Exception e) {
                    emitter.updateStatus(TaskState.TASK_STATE_FAILED,
                        emitter.messageBuilder()
                            .parts(List.of(new TextPart("Error: " + e.getMessage())))
                            .build());
                }
            }
        };
    }
}

The flow maps directly to the Task lifecycle:

Client sends SendMessage
  → execute() called
  → emitter.startWork()          → Task state: WORKING
  → scheduleService.chat()       → LLM + tool calls happen
  → emitter.addArtifact()        → Attach response content
  → emitter.complete()           → Task state: COMPLETED
  → Response returned to client

Show VenueAgentConfig.java (Spring Boot wiring) 
@Configuration
public class VenueAgentConfig {

    @Bean
    public VenueService venueService(ChatModel model,
                                      VenueTool venueTool) {
        return AiServices.builder(VenueService.class)
                .chatModel(model)
                .tools(venueTool)
                .build();
    }

    @Bean
    public AgentCard agentCard() {
        return AgentCard.builder()
                .name("Venue & On-Site Operations Agent")
                .version("1.0.0")
                .supportedInterfaces(List.of(
                    new AgentInterface(
                        TransportProtocol.HTTP_JSON.asString(),
                        "http://localhost:8081")))
                .capabilities(AgentCapabilities.builder()
                        .streaming(false)
                        .pushNotifications(false).build())
                .skills(List.of(
                    AgentSkill.builder().id("room-capacity")
                        .name("Room Capacity").build(),
                    AgentSkill.builder().id("indoor-map")
                        .name("Indoor Map").build(),
                    AgentSkill.builder().id("catering-queue")
                        .name("Catering Queue").build(),
                    AgentSkill.builder().id("entry-pass")
                        .name("Entry Pass").build()
                ))
                .build();
    }

    @Bean
    public AgentExecutor agentExecutor(VenueService venueService) {
        return new AgentExecutor() {
            @Override
            public void execute(RequestContext ctx, AgentEmitter emitter) {
                String userText = extractText(ctx.getMessage());
                emitter.startWork();
                String response = venueService.chat(userText);
                emitter.addArtifact(
                    List.of(new TextPart(response)),
                    null, "response", null);
                emitter.complete();
            }
        };
    }
}

The client code

Three steps: fetch the AgentCard, build a Client, send messages. Compare this to the Python test_interop.py — the pattern is the same, the language is different.

Show TravelAgentClient.java 
// 1. Fetch the Python agent's AgentCard
AgentCard card = A2A.getAgentCard("http://localhost:9000");
System.out.println("Agent: " + card.name());
for (AgentSkill skill : card.skills()) {
    System.out.println("  - " + skill.name() + ": " + skill.description());
}

// 2. Build the A2A client from the AgentCard
Client client = Client.builder(card)
    .withTransport(RestTransport.class,
        new RestTransportConfigBuilder())
    .build();

// 3. Send a message and handle the response
Message message = A2A.toUserMessage(
    "How do I get from the airport to the venue quickly?");
CountDownLatch latch = new CountDownLatch(1);

client.sendMessage(message,
    List.of((ClientEvent event, AgentCard ac) -> {
        if (event instanceof TaskEvent taskEvent) {
            var task = taskEvent.getTask();
            for (Artifact artifact : task.artifacts()) {
                for (Part<?> part : artifact.parts()) {
                    if (part instanceof TextPart tp) {
                        System.out.println(tp.text());
                    }
                }
            }
        }
        latch.countDown();
    }),
    error -> System.err.println("Error: " + error.getMessage())
);

latch.await(30, TimeUnit.SECONDS);
client.close();

1 Declare A2A Client Agents

Each downstream A2A agent is wrapped as a LangChain4j sub-agent using @A2AClientAgent. The framework automatically fetches the AgentCard and handles A2A communication. Use the @V annotation on parameters to bind them as agentic scope variables.

Show ScheduleAdvisorA2AAgent.java (one per remote agent) 
import dev.langchain4j.agentic.declarative.A2AClientAgent;
import dev.langchain4j.service.V;

public interface ScheduleAdvisorA2AAgent {

    @A2AClientAgent(
            a2aServerUrl = "http://localhost:8080",
            name = "Schedule & Content Advisor",
            description = "Answers questions about conference sessions, schedules, speakers, and talk content",
            outputKey = "response"
    )
    String ask(@V("query") String query);
}

2 Supervisor Agent

The @SupervisorAgent is the brain of the orchestrator. The LLM autonomously decides which sub-agents to call based on the user’s question, then synthesizes a unified response.

Show OrchestratorSupervisor.java 
public interface OrchestratorSupervisor {

    @SystemMessage("""
            You are the DevSphere conference concierge for Devoxx Belgium 2026
            at Kinepolis Antwerp.
            You coordinate specialist agents to answer attendee questions.
            Use the available agents to gather information, then synthesize
            a clear, helpful response.
            """)
    @SupervisorAgent(
            name = "DevSphere Orchestrator",
            description = "Orchestrates specialist agents to answer complex, multi-domain questions",
            subAgents = {
                    ScheduleAdvisorA2AAgent.class,
                    VenueA2AAgent.class,
                    TravelA2AAgent.class,
                    ExpenseA2AAgent.class
            }
    )
    String orchestrate(String query);
}
💡 No manual routing needed

Unlike a hand-coded decompose/dispatch/aggregate loop, the @SupervisorAgent lets the LLM decide which agents to call and how to combine results. Add a new @A2AClientAgent sub-agent and the supervisor automatically learns to use it.

3 REST Endpoint & Web UI

The orchestrator is not an A2A agent itself — it’s the user-facing entry point. A simple JAX-RS resource exposes POST /api/query and a built-in web UI at the root lets you chat interactively.

Show OrchestratorResource.java 
@Path("/api")
public class OrchestratorResource {

    @Inject
    OrchestratorSupervisor supervisor;

    @POST
    @Path("/query")
    @Consumes(MediaType.APPLICATION_JSON)
    @Produces(MediaType.APPLICATION_JSON)
    public QueryResponse query(QueryRequest request) {
        String response = supervisor.orchestrate(request.query());
        return new QueryResponse(response);
    }

    public record QueryRequest(String query) {}
    public record QueryResponse(String response) {}
}

Troubleshooting

⚠ Connection refused on Ollama

Make sure podman-compose up -d is running and the model has been pulled. Check with: curl http://localhost:11434/api/tags

⚠ Empty or slow responses

The first LLM call can be slow while Ollama loads the model into memory. Increase the timeout if needed.

⚠ "No sessions found"

Verify that session.data.path in application.properties points correctly to conference-data/sessions.json relative to the project directory.

⚠ A2A SDK not found

The A2A Java SDK is not on Maven Central. Build it from source: git clone https://github.com/a2aproject/a2a-java-sdk.git && cd a2a-java-sdk && mvn install -DskipTests

⚠ Python agent won't start

Make sure you activated the virtual environment (source .venv/bin/activate) and installed dependencies (pip install -e .). Python 3.11+ is required.

⚠ Port conflict

If port 8080 is already in use, check that no other agent or service is running on that port. The Schedule Advisor (Quarkus) runs on 8080 and the Expense Agent (WildFly) uses -Djboss.socket.binding.port-offset=2 to run on 8082.
